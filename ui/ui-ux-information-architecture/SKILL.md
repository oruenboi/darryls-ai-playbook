# UI UX Information Architecture

## Objective
Define user journeys, task flow, and content hierarchy so feature work is structurally correct before component design.

## Workflow
For review-only work, report problems without changing flows or copy. Reuse established journeys for narrow refinements; produce only the artifacts needed for the current decision.

1. Map end-to-end journey from entry point to completion outcome.
2. Break workflow into steps and identify friction, drop-off risk, and edge cases.
3. Design navigation layers: primary, secondary, and contextual routes.
4. Prioritize content and actions by user intent.
5. Apply progressive disclosure for advanced controls and details.
6. Deliver IA artifacts and UX decisions for downstream design-system work.

## Design Principles
- Optimize for task completion, not visual novelty.
- Minimize interaction count and decision fatigue.
- Keep naming predictable and aligned to user mental models.
- Separate summary views from deep detail and drill-down.
- Reduce competing signals to keep primary actions obvious.

## Deliverable Format
- User journey map with key stages and risk points.
- Task-flow model including interrupts and resume paths.
- Navigation structure and labeling rules.
- Content-priority matrix for each major screen.
- Open questions needing stakeholder alignment.

## Layer Position
Own task and information structure when it changes; an established flow need not be redesigned before a local component fix.
